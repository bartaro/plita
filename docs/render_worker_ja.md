# plita 描画ワーカー

説明書更新日：2026-10-25。Cargoパッケージ版：0.0.1。

## 対象と利用方法

`PlitaProgram`を実装するアプリが利用できる、任意の描画経路です。
GPU 描画と画面への提示が UI の更新や入力を待たせないようにします。既存アプリは同期描画のままです。

既存の `PlitaProgram` 実装に次のメソッドを追加すると有効になります。

```rust
fn render_on_worker_thread(&self) -> bool {
    true
}
```

メインウィンドウと、そのアプリの補助ウィンドウの両方に適用します。
設定は各レンダラーの生成時に読み取ります。実行中の切り替えスイッチではありません。
`continuous_redraw = false` のアプリも利用できます。

## スレッドの担当

| イベントループ側 | 描画ワーカー側 |
| --- | --- |
| OS ウィンドウと WGPU surface の作成 | 既に作成済みのレンダラーを所有 |
| キー、マウス、IME、ファイルドロップ | 頂点生成、画像アップロード、GPU 描画、提示 |
| `PlitaProgram::tick`、`resize`、UI 更新 | 受け取ったサイズと DPI のレンダラーへの適用 |
| `draw_list` / `auxiliary_draw_list` の生成 | 最新の描画リストの消費 |
| 補助ウィンドウの開閉、エラー処理 | 描画結果とエラーの通知 |

アプリ本体や UI 状態を別スレッドへ移しません。`PlitaProgram` に `Send` は要求しません。
Windows のネイティブウィンドウハンドルはイベントループ側で取得し、描画ワーカーから取得しません。
各ウィンドウは独立した描画ワーカーを持ちます。

## DPIと入力の扱い

`scale_factor_changed(scale_factor)`はメインウィンドウの初回描画前と、DPIの再取得・変更時の`resize`より前にイベントループ上で呼ばれます。論理1単位に対する物理ピクセル数を渡します。レイアウトと入力の当たり判定は論理座標を維持し、アプリ側で同じ倍率を二重適用しないでください。補助ウィンドウ固有のDPIを知らせるコールバックではありません。

`ime_allowed()`はメイン・補助ウィンドウ作成時の設定で、既定値は`true`です。物理キー中心のアプリは`false`を返せます。描画ワーカーの有効・無効とは独立しており、別のネイティブファイルダイアログのIMEには影響しません。

## フレームと共有画像

- 描画が遅い場合は、待機中の描画リスト、サイズ、DPI、再描画要求を最新の状態にまとめます。
- 途中の表示フレームは省略できます。アプリの tick や音楽・シミュレーション処理を省略する機能ではありません。
- 待機中のリストは一つだけ保持します。遅れたフレームを無制限に蓄積しません。
- 共有 RGBA 画像は、描画時にピクセルを複製してからロックを解除し、その後に GPU へ送ります。
- アプリは画像全体の更新を同じ mutex の中で行ってください。長い処理や GPU 待ちを画像のロック内で行わないでください。
- 共有画像は描画リスト生成時点ではなく、ワーカーが読み取った時点の最新の画像になります。

補助ウィンドウの描画リストを保持したい場合は、`auxiliary_draw_revision(id)` で
`Some(revision)` を返します。表示内容（ホバーや押下状態を含む）が変わるたびに
版番号を変え、`UiResponse` で再描画も要求してください。リサイズや DPI 変更では
保持内容を無効化します。アニメーションや共有画像を表示する補助ウィンドウでは
既定の `None` を使い、必要なフレーム更新を継続してください。

これはフレーム単位の厳密な録画・書き出し API ではありません。全フレーム保存が必要な処理には別の保存経路を用意してください。

## 完了、エラー、終了

描画要求は GPU 完了を待たずに戻り、内部の `FrameStats` は直近に完了したフレームの値になります。
初回完了前の `frame_index` は 0 です。
イベントループは完了とエラーを回収します。常時再描画しないアプリでも、描画が残っている間は 10 ms 間隔で確認し、完了後は通常の入力待ちに戻ります。
GPU エラーは同期描画と同じイベントループのエラー処理へ渡します。ワーカーの切断もエラーとして扱います。

閉じる際は新しい要求を停止し、待機中の処理を破棄します。現在の GPU 処理が戻った後にワーカーが終了します。
UI スレッドは終了待ちでブロックしません。GPU ドライバー自体の停止・ハングを強制解除する機能ではありません。

## 制約と検証

GPU 待ちを分離する機能であり、重い `tick`、UI レイアウト、描画リストの生成を自動的に並列化するものではありません。
音声など時間に敏感な処理は、引き続き小さい更新単位と適切なバッファを使ってください。

`plita_window` のテストで、要求の集約、遅い描画中の更新、終了、完了・切断通知を確認します。
Windows のネイティブ検証は次の個別コマンドで実行できます。

```powershell
cargo test -p plita_window native_worker_renderer_initializes_resizes_and_reopens -- --ignored --test-threads=1
cargo test -p plita_window native_auxiliary_renderer_initializes_resizes_and_reopens -- --ignored --test-threads=1
```

テストアプリは MZB-RS を使わず、`Rc<Cell<_>>` の UI 状態をイベントループ側に残したまま、共有画像の表示、最小化、新しいアクティブ化要求による同じウィンドウの復元、リサイズ、補助ウィンドウの終了と再生成を確認します。

## 2026-10-18 の公開時検証

検証上の制約（2026-10-18）：公開作業環境では、通常のワークスペース試験、GPUのオフスクリーン回帰試験2件、同期描画のネイティブウィンドウ試験が成功しました。一方、描画ワーカーのネイティブ試験は復元・リサイズ後にタイムアウトし、別のデスクトップ実行では異常終了しました。原因は未特定で、この環境でのワーカーの正常動作は確認できていません。安定動作が必要な場合は既定の同期描画を維持し、任意の描画ワーカーは対象環境で検証してから有効にしてください。

## DPI付きオフスクリーン出力

任意の`offscreen_fixture_snapshot_with_dpi`試験は、`PLITA_DRAW_FIXTURE`の描画リストと`scale_factor`（省略時1.0）を読み、`PLITA_GPU_EVIDENCE`へ`gpu.json`と物理サイズの`desktop.rgba`を出力します。GPUと明示的に用意した入力が必要です。検証対象はオフスクリーン描画経路で、ネイティブウィンドウの表示確認ではありません。

`cargo test -p plita_render --locked offscreen_fixture_snapshot_with_dpi -- --ignored --test-threads=1`で実行します。通常の試験成功と、実画面での描画・入力の確認は分けて記録してください。
