PLITA — 利用・開発マニュアル

DAISUKE OBA · ソース版 2026-10-11 · Cargoパッケージ版 0.0.1

1. 同梱内容

PLITAは、デスクトップの制作アプリを作るためのRust製GUI基盤です。このリポジトリには5個の基盤クレートと3個の実行可能なサンプルを同梱しています。ネイティブウィンドウ、入力処理、GPU描画、ウィジェット、ドッキング、キャンバスのモデルを提供します。個別エミュレーターのGUI、ROM、ビルド済み実行ファイルは含みません。

  • plita：公開APIとpreludeによる再公開、任意のPython補助機能。
  • plita_app：Appビルダーと起動設定。
  • plita_window：ネイティブイベントループとPlitaProgramインターフェース。
  • plita_render：GPUリソースと描画。
  • plita_ui：座標、描画リスト、ウィジェット、ドッキング、キャンバス、履歴のモデル。

2. 必要環境とビルド

Git、Rust 1.92以降、および対象環境用のリンカー・開発ツールを用意してください。WindowsのMSVCターゲットでは、Visual Studio Build ToolsのC++開発機能とWindows SDKが必要です。ウィンドウの表示には対応するGPUとドライバーも必要です。初回ビルドではCargoの依存関係をダウンロードします。再現性のためCargo.lockを保持してください。

git clone https://github.com/bartaro/plita.git
cd plita
cargo check --workspace --locked
cargo test --workspace --locked

ワークスペースではwgpuのDX12・GLES・Vulkanバックエンドを明示的に有効化しています。マニフェストでMetalは有効になっていません。すべてのOSやGPU構成で検証済みとは限らず、対象環境固有の依存関係や表示用ライブラリの準備が必要な場合があります。上のコマンドは検証手順であり、全環境での試験完了を示すものではありません。

3. サンプルの起動

リポジトリのルートで、以下を1つずつ実行します。次のサンプルを起動する前にウィンドウを閉じてください。

cargo run --locked -p hello_plita
cargo run --locked -p docking_demo
cargo run --locked -p canvas_demo

現在の3サンプルは同じCreativeShellを起動し、ウィンドウのタイトルと、canvas_demoでは初期サイズが異なります。名前ごとに別の完成済みアプリが実装されているわけではありません。共通シェルにはメニューバー、ツール列、グリッドとアートボードのキャンバス、インスペクター、タイムライン、ステータスバーがあります。共通UIを試し、個別機能を組み込む際はソースも参照してください。

文字入力欄やメモリー入力欄にフォーカスがない状態で、次の操作を試せます。

  • 1 / V：選択、2 / H：パン、3 / R：矩形、4 / T：文字、5 / G：グリッド。パンツールでキャンバスをドラッグし、ホイールで拡大縮小、Fで表示をリセットします。
  • オブジェクトを選択して本体や角のハンドルをドラッグできます。Ctrl+Dで複製、Delete / Backspaceで削除、矢印キーで1ワールド単位、Shift＋矢印キーで10単位移動します。Ctrl+Zで取り消し、Ctrl+Y / Ctrl+Shift+Zでやり直します。
  • Ctrl+1からCtrl+6でプロパティ・レイヤー・メモリー・タイムライン・ログ・診断の各パネルを選択します。Ctrl+Shift+1からCtrl+Shift+6でフローティングパネルを開き、Ctrl+0で閉じます。Mでメモリーエディターの表示を切り替えます。
  • このデモのCtrl+Sはステータスバーにスナップショットのサイズを表示し、ファイルには保存しません。Ctrl+Oはデモ文書をリセットします。完成した保存・読み込みダイアログとして扱わないでください。

4. アプリの起動方法

hello_plitaのエントリーポイント全体は次のとおりです。

use plita::prelude::*;

fn main() -> Result<()> {
    App::new()
        .title("PLITA UI v1.0 - Creative Shell")
        .window_size(1280, 800)
        .clear_color(ClearColor::rgb(0.105, 0.111, 0.125))
        .continuous_redraw(false)
        .run()
}

App::new()でAppBuilderを作り、run()で標準シェルを起動します。独自の状態を持つアプリでは、初期Sizeを受け取りPlitaProgram実装を返すファクトリーをrun_programに渡します。resize・handle_event・draw_listを実装し、周期的な更新が必要ならtickを利用します。OSのイベント処理内から直接描画するのではなく、UiResponseで必要なUIの応答を返します。

continuous_redraw(false)では、更新や再描画要求に応じて描画します。連続描画は必要なアプリで有効にしてください。draw_listは描画命令を記述し、GPUへの送信はレンダラーが担当します。

5. 入力と補助ウィンドウ

UIの当たり判定とレイアウトにはPLITAの論理座標を使います。DPI変換はウィンドウ層が担当します。ポインター、キーボード、IME、ファイルドロップのイベントがあります。受け取ったファイルパスの読み込み、解析、保存はアプリ側で実装してください。

PointerDoubleClickは2回目のPointerUpの後に届きます。同じボタンで完了した2回のクリックが500 ms以内、位置の差が6論理ピクセル以内のときに認識します。ドラッグ操作は除外し、各ネイティブウィンドウで独立して判定します。

独自アプリではAuxiliaryWindowDescriptorで補助ウィンドウを定義し、そのリサイズ・イベント・描画リストのコールバックを実装できます。標準シェルの分離したメモリーエディターが扱うのはシェル内のデモ用バッファです。エミュレーターや別プロセスへ自動接続する機能ではありません。

6. ドッキング、キャンバス、保存

DockLayoutStateとドック座標の型でパネルの配置を表します。DockLayoutProfileはバージョン付きレイアウトプロファイルです。シェルはプロファイルのテキストを扱え、AppBuilder::startup_layout_profileで標準シェル起動時に復元できます。そのテキストをいつ、どこに保存するかはアプリで決めてください。メモリー内のレイアウトスロットはファイルへの永続保存の代わりにはなりません。

CanvasDocumentとLayerNodeは文書とレイヤーのモデルです。選択、矩形選択、スナップの補助機能とCommandHistoryを使って編集操作を組み立てられます。CommandRegistryとCommandDescriptorはコマンドとショートカットの情報を記述します。完成したアプリ用ファイル形式や自動プロジェクト保存を提供するAPIではありません。モデルと独自コマンド、シリアライズ処理を接続してください。

7. フォントとアイコン

RobotoとRoboto Monoをassets/fontsに同梱しています。PLITAはfontdueで文字をラスタライズし、小型ビットマップの代替描画も保持しています。インストール済みのシステムフォントも検索します。PLITA_UI_FONT・PLITA_UI_FONT_FALLBACK・PLITA_MEMORY_FONTでフォントファイルを指定する場合は、アプリ起動前に設定してください。表示したい文字を含むフォントが必要です。同梱のラテン文字用フォントだけでは日本語・中国語・韓国語を網羅しません。

active_font_family・active_font_source・active_text_backend・active_memory_font_familyで使用中のフォントを調べられます。実行ファイルを移動する際はアセットの参照先を維持するか、適切なフォントパスを設定してください。ローダーにシステムフォントのパスが書かれていても、そのフォントファイルを同梱しているわけではありません。

LucideのSVGアイコンを52個同梱しています。lucide_icon_names()で対応名を取得し、draw_lucide_iconで描画します。crates/plita_ui/assets/build_icons.pyでRustのパスデータを再生成する場合も、SVGとライセンス表示を保持してください。

8. 任意の描画ワーカー

PlitaProgram実装に次のメソッドを追加すると有効になります。

fn render_on_worker_thread(&self) -> bool {
    true
}

GPU処理と画面への提示を各ウィンドウのワーカーが担当します。ウィンドウ管理、入力、tick、描画リストの構築はイベントループ側に残ります。描画が遅いときは待機中の要求を最新フレームに集約するため、全フレームを保存する録画APIではありません。共有RGBA画像の全体更新は同じmutexの中で行い、ロックを短く保ってください。設定はレンダラー生成時に読み取るもので、実行中の切り替えスイッチではありません。既定は同期描画です。

9. 任意のPython補助機能

Python 3.10以降と、1.8以上2未満のmaturinを適切なPython環境に用意してください。リポジトリのルートから次を実行します。

cd crates/plita
maturin develop --features python

python機能は、共通の値の型を包むPyO3クラスと登録用の補助関数を提供します。RustのGUI全体が自動的にPythonアプリになるわけではありません。#[pyclass]や#[pymodule]を使うアプリのクレートには、マクロが::pyo3を参照するため、任意のpyo3依存関係も必要です。前の節のコマンドに戻る場合は、作業ディレクトリをリポジトリのルートに戻してください。

10. 問題の切り分けと検証

  • ビルド失敗：最初のコンパイラーまたはリンカーのエラーを確認し、Rustの版と対象ツールチェーンを確認します。ロックファイルを保持してください。
  • ウィンドウが出ない・GPU初期化失敗：ログとグラフィックスドライバーを確認します。ビルド成功だけではGUI動作の確認にはなりません。
  • 文字が欠ける：対象文字を持つフォントを指定し、active_font_sourceを確認します。
  • UIが止まる：イベント処理、tick、描画リスト生成を短く保ちます。描画ワーカーはアプリのロジックを並列化しません。
  • ネイティブウィンドウの試験には操作可能なデスクトップが必要です。通常の単体試験とは別に表示を確認してください。

PowerShellで診断ログを有効にする例です。

$env:RUST_LOG="debug,plita_window=trace,plita_render=trace"
cargo run --locked -p hello_plita

本書は公開ソースの説明であり、すべての環境での動作試験完了を保証するものではありません。cargo doc --workspace --no-deps --lockedでAPI文書も生成できます。

11. ライセンスと再配布

PLITAのコードと本書はMITライセンスで、著作権者は2026 DAISUKE OBAです。コピーや主要部分の再配布ではMITの著作権表示と許諾文を保持してください。第三者のアセットには元のライセンスが適用されます。Roboto・Roboto MonoはOFL-1.1、LucideはISCで、由来となったFeatherのMIT表示も含みます。

LICENSE、第三者の権利表示、依存関係の表示、アセットの出典を確認してください。フォント、アイコン、バイナリを配布するときは対応する表示を同梱します。macOSバイナリの配布前には、dispatchとmalloc_bufについて記録した独立した許諾文の不足を解決してください。このリポジトリはソースと表示文書の公開であり、将来のバイナリ配布では実際にリンクする依存関係の確認が必要です。
