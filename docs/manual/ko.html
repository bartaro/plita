plita — 사용자 및 개발자 설명서

DAISUKE OBA · 소스 배포판 2026-10-18 · Cargo 패키지 버전 0.0.1

1. 포함된 구성 요소

plita는 데스크톱 제작 도구를 위한 Rust GUI 기반 라이브러리입니다. 이 저장소에는 프레임워크 크레이트 5개와 실행 가능한 예제 3개가 들어 있습니다. 네이티브 창, 입력 처리, GPU 렌더링, 위젯, 도킹 및 캔버스 모델을 제공합니다. 개별 에뮬레이터의 GUI, ROM, 빌드된 실행 파일은 포함하지 않습니다.

  • plita: 공개 API와 prelude 재노출, 선택적 Python 도우미.
  • plita_app: App 빌더와 시작 설정.
  • plita_window: 네이티브 이벤트 루프와 PlitaProgram 인터페이스.
  • plita_render: GPU 리소스와 렌더링.
  • plita_ui: 좌표, 그리기 목록, 위젯, 도킹, 캔버스 및 이력 모델.

2. 요구 사항과 빌드

Git, Rust 1.92 이상, 대상 환경용 링커와 개발 도구를 설치하세요. Windows MSVC 대상에는 Visual Studio Build Tools의 C++ 개발 도구와 Windows SDK가 필요합니다. 창을 표시하려면 호환되는 GPU와 드라이버도 필요합니다. 첫 빌드에서는 Cargo 의존성을 다운로드합니다. 재현 가능한 빌드를 위해 Cargo.lock을 유지하세요.

git clone https://github.com/bartaro/plita.git
cd plita
cargo check --workspace --locked
cargo test --workspace --locked

워크스페이스는 wgpu의 DX12, GLES, Vulkan 백엔드를 명시적으로 활성화합니다. 매니페스트에서 Metal은 활성화하지 않습니다. 모든 운영 체제와 GPU 구성이 검증되었다고 가정하지 마세요. 대상별 의존성과 디스플레이 라이브러리에 추가 설정이 필요할 수 있습니다. 위 명령은 검증 절차이며 모든 환경의 시험 통과를 뜻하지 않습니다.

3. 예제 실행

저장소 루트에서 한 번에 하나씩 실행하세요. 다음 예제를 실행하기 전에 창을 닫으세요.

cargo run --locked -p hello_plita
cargo run --locked -p docking_demo
cargo run --locked -p canvas_demo

현재 세 예제는 모두 같은 CreativeShell을 실행합니다. 창 제목이 다르며 canvas_demo는 초기 크기도 다릅니다. 이름이 서로 다른 완성된 애플리케이션을 의미하지는 않습니다. 공통 셸에는 메뉴 모음, 도구 모음, 격자와 아트보드가 있는 캔버스, 인스펙터, 타임라인 및 상태 표시줄이 있습니다. 공통 UI를 살펴보고 개별 기능을 통합할 때 소스를 참고하세요.

텍스트 및 메모리 입력란에 포커스가 없을 때 다음 조작을 사용할 수 있습니다.

  • 1 / V: 선택, 2 / H: 이동, 3 / R: 사각형, 4 / T: 텍스트, 5 / G: 격자. 이동 도구로 캔버스를 드래그하고 휠로 확대·축소하며 F로 화면을 초기화합니다.
  • 객체나 모서리 핸들을 선택해 드래그합니다. Ctrl+D는 복제, Delete / Backspace는 삭제, 방향키는 월드 좌표 1단위 이동, Shift + 방향키는 10단위 이동입니다. Ctrl+Z는 실행 취소, Ctrl+Y / Ctrl+Shift+Z는 다시 실행입니다.
  • Ctrl+1부터 Ctrl+6까지는 속성, 레이어, 메모리, 타임라인, 로그, 진단 패널을 선택합니다. Ctrl+Shift+1부터 Ctrl+Shift+6까지는 플로팅 패널을 열고 Ctrl+0은 닫습니다. M은 메모리 편집기 표시를 전환합니다.
  • 이 데모에서 Ctrl+S는 상태 표시줄에 스냅샷 크기만 표시하며 파일을 저장하지 않습니다. Ctrl+O는 데모 문서를 초기화합니다. 완성된 파일 저장·열기 대화 상자로 생각하지 마세요.

4. 애플리케이션 시작

다음은 hello_plita의 전체 진입점입니다.

use plita::prelude::*;

fn main() -> Result<()> {
    App::new()
        .title("plita UI v1.0 - Creative Shell")
        .window_size(1280, 800)
        .clear_color(ClearColor::rgb(0.105, 0.111, 0.125))
        .continuous_redraw(false)
        .run()
}

App::new()는 AppBuilder를 만들고 run()은 기본 셸을 실행합니다. 자체 상태를 사용하는 앱은 초기 Size를 받아 PlitaProgram 구현을 반환하는 팩터리를 run_program에 전달합니다. resize, handle_event, draw_list를 구현하고 주기적 갱신이 필요하면 tick을 사용하세요. OS 이벤트 콜백에서 직접 그리는 대신 UiResponse로 필요한 UI 응답을 반환하세요.

continuous_redraw(false)에서는 갱신과 다시 그리기 요청에 따라 화면을 그립니다. 앱에 필요한 경우에만 연속 다시 그리기를 활성화하세요. draw_list는 그리기 명령을 기술하고 GPU 제출은 렌더러가 담당합니다.

5. 입력과 보조 창

UI 적중 검사와 배치에는 plita의 논리 좌표를 사용하세요. DPI 변환은 창 계층이 처리합니다. 포인터, 키보드, IME 및 파일 드롭 이벤트를 제공합니다. 전달받은 파일 경로를 열고 분석하고 저장하는 작업은 앱에서 구현해야 합니다.

PointerDoubleClick은 두 번째 PointerUp 뒤에 전달됩니다. 같은 버튼으로 완료한 두 클릭의 간격이 500 ms 이내이고 위치 차이가 6 논리 픽셀 이내여야 합니다. 드래그는 제외하며 각 네이티브 창은 독립적으로 판정합니다.

AuxiliaryWindowDescriptor로 보조 창을 정의하고 해당 창의 크기 변경, 이벤트 및 그리기 목록 콜백을 구현할 수 있습니다. 셸의 분리된 메모리 편집기는 셸이 보유한 데모 버퍼를 다룹니다. 에뮬레이터나 다른 프로세스에 자동으로 연결하지 않습니다.

PlitaProgram::minimum_window_size()와 auxiliary_window_minimum_size(id)는 논리 좌표로 클라이언트 영역의 최소 크기를 지정합니다. 기본값 None은 크기를 제한하지 않습니다. auxiliary_window_activation_request(id)는 선택적 요청 토큰을 반환합니다. 의도적으로 복원하거나 포커스를 요청할 때마다 값을 바꾸세요. 같은 토큰은 창을 반복해서 활성화하지 않습니다. 보조 창 생성 실패 후에는 창 정의를 철회하거나 토큰을 변경하여 재시도할 수 있으며, 주 창은 계속 실행됩니다.

auxiliary_draw_revision(id)로 보조 창의 그리기 목록을 유지할 수 있습니다. Some(revision)을 반환하면 호버 및 누름 상태를 포함한 표시 내용이 바뀔 때마다 버전을 변경하고 UiResponse로 다시 그리기도 요청하세요. 창 크기 또는 DPI 변경은 캐시를 무효화합니다. 애니메이션이나 공유 이미지 창에서는 기본값 None을 반환하세요. 최소화된 창은 렌더링하지 않으며 크기가 0인 크기 변경 이벤트는 무시합니다.

6. 도킹, 캔버스와 저장

DockLayoutState와 도킹 기하 타입은 패널 배치를 나타냅니다. DockLayoutProfile은 버전 정보가 있는 배치 프로필입니다. 셸은 프로필 텍스트를 처리하며 AppBuilder::startup_layout_profile로 기본 셸 시작 시 복원할 수 있습니다. 텍스트를 언제 어디에 저장할지는 앱이 결정해야 합니다. 메모리의 배치 슬롯은 영구 파일 저장을 대신하지 않습니다.

CanvasDocument와 LayerNode는 문서와 레이어 모델입니다. 선택, 영역 선택, 스냅 도우미와 CommandHistory로 편집 동작을 구성할 수 있습니다. CommandRegistry와 CommandDescriptor는 명령과 단축키 정보를 나타냅니다. 이 API는 완성된 앱 파일 형식이나 자동 프로젝트 저장 기능을 제공하지 않습니다. 자체 명령과 직렬화에 모델을 연결하세요.

memory_viewer_address_at_point(rect, base_address, byte_count, position)는 draw_memory_viewer에 보이는 16진수 바이트 위치를 Option<u16> 주소로 변환합니다. 그릴 때와 같은 사각형과 시작 주소, 실제 바이트 수, 논리 포인터 좌표를 전달하세요. 주소 레이블, ASCII 영역, 간격, 없는 바이트 및 숨겨진 행은 None입니다. 선택과 쓰기는 앱이 처리하며 이 함수는 메모리를 수정하지 않습니다.

7. 글꼴과 아이콘

Roboto와 Roboto Mono를 assets/fonts에 포함합니다. 텍스트는 fontdue로 래스터화하며 작은 비트맵 대체 글꼴도 유지합니다. 설치된 시스템 글꼴도 검색합니다. PLITA_UI_FONT, PLITA_UI_FONT_FALLBACK, PLITA_MEMORY_FONT로 파일을 지정할 때는 앱 실행 전에 설정하세요. 글꼴에는 표시할 문자가 있어야 합니다. 포함된 라틴 문자 글꼴만으로는 한국어·중국어·일본어를 모두 표시할 수 없습니다.

active_font_family, active_font_source, active_text_backend, active_memory_font_family로 글꼴 선택을 진단할 수 있습니다. 실행 파일을 옮기면 자산 경로를 유지하거나 적절한 글꼴 경로를 설정하세요. 로더에 시스템 글꼴 경로가 있다고 해서 해당 글꼴 파일이 배포에 포함된 것은 아닙니다.

Lucide SVG 아이콘 52개를 포함합니다. lucide_icon_names()로 이름을 확인하고 draw_lucide_icon으로 그립니다. crates/plita_ui/assets/build_icons.py로 Rust 경로 데이터를 다시 생성할 때도 SVG와 라이선스 고지를 유지하세요.

8. 선택적 렌더링 작업 스레드

PlitaProgram 구현에 다음 메서드를 추가하면 활성화됩니다.

fn render_on_worker_thread(&self) -> bool {
    true
}

창마다 작업 스레드가 GPU 처리와 화면 표시를 맡습니다. 창 관리, 입력, tick, 그리기 목록 생성은 이벤트 루프 스레드에 남습니다. 렌더링이 느리면 대기 요청을 최신 프레임으로 합치므로 모든 프레임을 기록하는 API가 아닙니다. 공유 RGBA 이미지 전체를 같은 mutex 안에서 갱신하고 잠금 시간을 짧게 유지하세요. 설정은 렌더러 생성 시 읽으며 실행 중 전환 스위치가 아닙니다. 기본값은 동기 렌더링입니다.

렌더러는 불변 RGBA 원본을 유지하여 텍스처 캐시의 식별 충돌을 방지하고, 정점 버퍼와 이미지 임시 저장 공간을 재사용합니다. 사용하지 않는 이미지 캐시는 짧은 프레임 단위 유지 기간 후 해제됩니다. 공유 RGBA 데이터는 mutex 안에서 복사한 뒤 GPU로 전송하므로 같은 mutex 안에서 갱신하세요. 기존 그리기 목록 호출은 변경할 필요가 없습니다.

검증 제한(2026-10-18): 공개 작업 환경에서 일반 워크스페이스 시험, 오프스크린 GPU 회귀 시험 2건, 동기 렌더링의 네이티브 창 시험이 통과했습니다. 반면 네이티브 렌더 워커 시험은 복원 및 크기 변경 후 시간 초과가 발생했고, 별도의 데스크톱 실행은 비정상 종료되었습니다. 원인은 아직 확인되지 않았으며 이 환경에서 워커의 정상 동작은 검증되지 않았습니다. 안정성이 필요하면 기본 동기 렌더링을 유지하고, 선택적 워커는 대상 환경에서 검증한 후 활성화하세요.

9. 선택적 Python 도우미

적절한 Python 환경에 Python 3.10 이상과 maturin 1.8 이상, 2 미만을 준비하세요. 저장소 루트에서 실행합니다.

cd crates/plita
maturin develop --features python

python 기능은 공통 값의 PyO3 래퍼와 등록 도우미를 제공합니다. Rust GUI 전체를 완전한 Python 앱으로 자동 변환하지 않습니다. #[pyclass] 또는 #[pymodule]을 쓰는 앱 크레이트에는 매크로가 ::pyo3를 참조하므로 자체 선택적 pyo3 의존성도 필요합니다. 앞의 명령을 다시 사용할 때는 저장소 루트로 돌아가세요.

10. 문제 해결과 검증

  • 빌드 실패: 첫 컴파일러 또는 링커 오류를 읽고 Rust 버전과 대상 도구 체인을 확인하세요. 잠금 파일을 유지하세요.
  • 창이 열리지 않거나 GPU 초기화 실패: 로그와 그래픽 드라이버를 확인하세요. 빌드 성공만으로 GUI 동작이 검증되지는 않습니다.
  • 문자가 빠짐: 해당 문자를 포함한 글꼴을 선택하고 active_font_source를 확인하세요.
  • UI 멈춤: 이벤트 처리, tick, 그리기 목록 생성을 짧게 유지하세요. 렌더링 작업 스레드는 앱 로직을 병렬화하지 않습니다.
  • 네이티브 창 시험에는 대화형 데스크톱이 필요합니다. 일반 단위 시험은 시각적 검증을 대신하지 않습니다.

PowerShell에서 진단 로그를 활성화하는 방법입니다.

$env:RUST_LOG="debug,plita_window=trace,plita_render=trace"
cargo run --locked -p hello_plita

이 설명서는 공개 소스를 설명하며 모든 플랫폼의 실행 시험을 보증하지 않습니다. cargo doc --workspace --no-deps --locked로 API 문서도 생성할 수 있습니다.

GPU가 작동하는 환경에서는 외부 데이터 없이 두 회귀 시험을 명시적으로 실행할 수 있습니다: cargo test -p plita_render --locked offscreen_image_updates_and_draw_order -- --ignored --test-threads=1 및 cargo test -p plita_render --locked offscreen_cache_keeps_images_distinct_and_releases_old_sources -- --ignored --test-threads=1. 일반 워크스페이스 시험은 GPU 및 네이티브 데스크톱 시험을 건너뜁니다. 다른 ignored 벤치마크는 외부 입력과 출력 경로가 필요하므로 준비 없이 모든 ignored 시험을 실행하지 마세요.

11. 라이선스와 재배포

plita 코드와 이 설명서는 MIT 라이선스이며 저작권 표시는 (c) 2026 DAISUKE OBA입니다. 복제본이나 주요 부분을 재배포할 때 MIT 저작권 및 허가 고지를 유지하세요. 타사 자산은 자체 라이선스를 유지합니다. Roboto와 Roboto Mono는 OFL-1.1, Lucide는 ISC이며 원래 Feather의 MIT 고지도 포함합니다.

LICENSE, 타사 고지, 의존성 고지, 자산 출처를 확인하세요. 글꼴, 아이콘, 바이너리를 배포할 때 관련 고지를 포함하세요. macOS 바이너리를 배포하기 전에 dispatch와 malloc_buf에 기록된 독립된 허가문 누락을 해결해야 합니다. 이 저장소는 소스와 고지를 공개하며 향후 바이너리 배포에는 실제로 링크되는 의존성 검토가 필요합니다.
